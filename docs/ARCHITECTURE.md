# Architecture (Day 2)

PhysiCore Collector does four separable things. Each lives in its own modules and can be used without the others.

```
                         ┌──────────────────────────── needs ROS 2 only here ───────────────────────────┐
 profile.yaml ──► capture run ─► supervisor.py ─► recorder.py ──► `ros2 bag record` (child process)
 (schema 1.1)                       │  lifecycle,        adapter        writes <session>/bag/  (rosbag2's files)
                                    │  stop/kill, health boundary
                                    └──► <session>/capture_health.json   (atomic, rewritten on every event)
 ─────────────────────────────────────────────────────────────────────────────────────────────────────────
                         everything below is OFFLINE: no ROS 2, no rclpy, no network
 .mcap file ─────────────► mcap_reader.scan_recording ─────────────┐
 bag directory ─► bag.scan_bag ─► (each segment through the same   ├─► ScanResult ─► validation.validate_recording
   + metadata.yaml  bag_metadata    scan_recording, then merged)    │                    (+ bag:* and capture:* checks)
   + capture_health.json                                           │                          │
                                                                   └──────────────────────────┤
                                                    session.analyze_session ◄─────────────────┘
                                                                   │
                                          export.export_package ─► package dir (manifest.json, verified copies)
                                          export.verify_package ◄─ `package verify` (offline re-check)
```

## Module responsibilities

| Module | Responsibility | Must NOT |
|---|---|---|
| `mcap_reader` (Day 1, unchanged) | stream one MCAP file, framing/CRC check, topics, log_times | load payloads into memory |
| `bag_metadata` | strictly parse rosbag2 `metadata.yaml` into a summary; problems returned as messages | decide completeness; touch recordings |
| `bag` | discover and order segments, safety-check paths, scan each, cross-check metadata, merge into one `ScanResult`, emit `bag:*` checks | write/repair/move anything; trust file names for order |
| `capture_health` | sidecar schema, strict loader, `capture:*` checks | invent statistics; accept `appears_finalized=true` after an unclean state |
| `recorder` | the one place that knows how to start rosbag2 (`Rosbag2CliAdapter`) and the `RecorderAdapter` protocol | import rclpy; record messages |
| `supervisor` | start, watch, bounded stop, kill, inspect output, write sidecar | validate evidence against profiles; package |
| `validation`, `status` (Day 1) | derive status from checks; `extra_checks` hook added | know how many files a recording has |
| `export` | copy-hash-verify into a staging dir, atomic publish; `verify_package` | overwrite a target; copy un-accounted files |

## Why merge segments into one `ScanResult`

Day 1's validation, cadence analysis, manifest and export consume a `ScanResult`. Merging per-segment results (topics keyed by topic/schema/encoding, log_times concatenated, channel ids renumbered) means a split recording needs **no** change downstream, and a cadence gap that straddles a segment boundary is still detected (`test_gap_straddling_a_segment_boundary_is_still_seen`).

## State machines

**Capture state** (`capture_health.CaptureState`): `running` → exactly one of `stopped_clean` (graceful stop, exit 0), `stopped_with_error` (graceful stop, exit ≠ 0), `exited_unexpectedly` (recorder ended before any stop), `stop_timeout_killed`, `failed_to_start`, `supervisor_error`. If the supervisor itself dies, the last written state is `running` with a dead pid: `capture status` and validation read that as *interrupted*, never as running or complete.

**Segment state** (`SegmentState`): `readable | partially_readable | unreadable | missing | not_a_file | unsafe_path | unsupported`. `readable` means only that single file's MCAP framing/CRC checks passed.

**Session status** is unchanged from Day 1 (`complete | partial | failed`, `complete` is earned only when every required check passes). A bag reaches `complete` only if: `metadata.yaml` parsed, storage supported, every listed segment present and fully readable, no duplicate/conflicting/unlisted storage files, message counts agree, and (when a sidecar is supplied) the capture ended cleanly, nothing was reported lost, and the files are byte-identical to what the supervisor hashed at capture end.

## Compatibility rules (tested)

* Profile `1.0` loads unchanged; `capture:` requires `1.1`.
* A single-MCAP export writes manifest/report schema `0.1`, byte-identical in shape to Day 1 (`test_single_mcap_export_has_exactly_the_day1_shape` compares against a package generated by the untouched Day 1 code, `tests/compat/day1_package`). Day 2 sections appear only in `0.2` manifests; the `0.1` validator rejects Day 2 sections.
* `verify_package` accepts both versions; `package verify` works on the Day 1 package.
* `session inspect <file.mcap> --json` output is unchanged (no new keys for plain files).

## Security / safety properties (each has a test)

* Bag paths from `metadata.yaml`: absolute paths, `..`, NUL/backslash, and symlinks resolving outside the bag directory are refused and never hashed or copied.
* Topic names that `ros2 bag record` would parse as options (`-a`) are refused before anything starts.
* Capture never overwrites: the session directory is created exclusively; the bag directory is left to rosbag2.
* The sidecar environment is an allow-list of two names; the recorded command has the executable's base name and a placeholder instead of host paths.
* Staging directory is removed on any failure; originals are only ever read.

# Day 3 additions: unattended capture

```
 capture start ──► prepare(): session dir (exclusive) + byte-identical profile copy + STARTING record
        │
        └─ spawns, detached (own session, no tty, log file):  python -m physicore_collector capture _supervise <session>
                                  │
                       adopt(): requires state == STARTING; takes  <session>/supervisor.lock  (one supervisor per session)
                                  │                                <out>/.active-capture.lock (one ACTIVE capture per directory)
                                  ▼
                       execute(): recorder via trampoline (deterministic signals) ─ heartbeat ─ disk ─ stop file/signal ─ record
 capture service-run (systemd) = recover --all --stop-orphan ; then prepare+execute as launch_mode "service"
 capture recover  = settle sessions whose supervisor is gone (never edits evidence)
```

## Who is alive? Three separate questions (`liveness.assess`, read-only)

| Question | Authority | Never |
|---|---|---|
| Is a **supervisor** attached? | the session `flock` (the kernel drops it on any death) | a bare pid, or "cmdline contains physicore" |
| Is the **recorder** still running? | identity = pid + start time + boot id (`procident`) | signalling a process whose identity does not match |
| What does the **capture** amount to? | persisted state + the two facts above | claiming healthy on a stale/unwritten record |

The lock can lag a supervisor's death by milliseconds (the kernel keeps the shared fd table until the last thread exits,
while `/proc` already shows the leader as a zombie). The lock stays authoritative; recovery retries acquisition briefly.

## Capture state (health record schema 1.1; 1.0 still loads)

`starting` → `running` → one of: `stopped_clean`, `stopped_with_error`, `exited_unexpectedly`, `stop_timeout_killed`,
`failed_to_start`, `supervisor_error`, `stopped_disk_critical` (graceful stop by the supervisor, bag finalized, capture ended
early). `interrupted` is written only by `capture recover`. Assessment vocabulary: `starting | healthy | degraded |
interrupted | finalized | failed`. Only `stopped_clean` + a finalized bag is `finalized`; only `stopped_clean` lets validation
call the *capture* complete.

## Recorder start-up contract

The supervisor holds the read end of the recorder's output pipe and starts it in its own process group through a constant
trampoline that (a) resets SIGINT/SIGTERM/... to default and clears the signal mask (so a graceful stop works even if the
supervisor was launched from a backgrounded job or a test runner) and (b) keeps SIGPIPE ignored (so a dead supervisor never
kills the recorder on its next log line). The trampoline `exec`s, so the recorded identity is the recorder's.

# Day 4 additions: incident preparation

```
 capture run | _supervise | service-run (clean stop)          incident prepare <file | bag-dir | session-dir>
        │  (supervisor returned: final record written, locks released)         │
        └──────────────► incident.auto_prepare_after_capture ──────────────────┤
                                                                               ▼
   resolve_source ► liveness.assess (refuse if active) ► session.analyze_session ► fingerprint ► idempotency / conflict
        (bag.scan_bag, resolve_recording_input)              (validation, manifest, capture checks)
                                                                               ▼
      per-target flock ► free-space check ► staging ► export.export_package(staging/package) ► incident.json + summary ► rename
```

`incident.py` is orchestration only. It reuses `bag`, `session`, `validation`, `manifest`, `capture_health`, `liveness` and `export`
unchanged; no existing schema (manifest 0.1/0.2, report, sidecar 1.0/1.1, profile 1.0-1.2) changed. The incident result is a NEW file,
`incident.json` (schema 1.0), written next to the export package, never inside it (`verify_package` rejects unlisted files by design).

| Statement | Derived from | Never |
|---|---|---|
| `artifact_integrity` | `verify_package` (via `export_package`), three-way copy digests, `capture:output_unchanged` | claim completeness or absence of loss |
| `capture_health` | `liveness.assess` on the sidecar; `unknown` without one | treat a missing record as healthy |
| `evidence_coverage` | `topic_present:*`, `cadence:*`, `metadata:*`, trigger checks of the existing report | say "nothing missing" |
| `preparation` | success of the staged build + publish | exist for a failed attempt (no incident is published) |

The result vocabulary is the existing `complete | partial | failed` validation status plus `outcome: success | degraded`; `failure` is
the absence of a published incident (exit 2 and, for sessions, `incident_attempt.json`). Why hooks live in the CLI layer: the supervisor's
contract says it does not package. Why service mode prepares only after a clean stop: see OPERATIONS.md. Segment order comes from `bag.scan_bag`
(metadata, else observed `log_time`), recorded per segment in `incident.json` with its basis.

# Day 5 additions: safe background preparation

```
 capture ends ──► (run/_supervise) auto_prepare ─┐        service-run ends ──► defer_session (stat-only) ─┐
                                                 ▼                                                      ▼
   gate 1: active-capture lock in guarded dirs? ──yes──► DEFERRED ──► <session>/incident_attempt.json (queue entry, schema 1.1)
   gate 2: recorder alive (liveness) / file open for writing (/proc)? ──yes──► DEFERRED          ▲
        │ no                                                                                       │
        ▼                                                                                          │
   analyze (scan) ─► copy ─► verify ─► publish      every read/hash/copy chunk ─► checksums.io_hook ─► IoGovernor
        └───────── capture appeared? ──yes──► stop, remove staging, DEFERRED ──────────────────────┘
 incident pending list/run:  scan sessions ─► (idle only) recover_session (existing) ─► prepare_incident
```

One chokepoint, no daemon: `checksums.io_hook` is called by every bulk read/write (`sha256_file`, `read_and_hash`, `copy_and_hash`,
and the MCAP scan through `_BoundedReader.read`); `incident.IoGovernor` implements yielding and the optional throttle on it. The queue is the
per-session `incident_attempt.json` (1.1; adds `deferred`, `attempt_count`, `scheduled_by`, `guard_dirs`; 1.0 stays readable), discovered by
scanning, so it survives restarts with no new state format or lock. Capture locking, the supervisor, recovery and export are unchanged: the
scheduling race cannot be closed without making captures wait for preparation, which is refused on purpose, so it is bounded and documented.
